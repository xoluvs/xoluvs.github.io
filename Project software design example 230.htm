Executive Summary

 

Introduction and Problem Statement

Creative Technology Solutions (CTS) is partnering with a client, The Gaming Room, to expand their Android only application into a scalable web-based games, usable across multiple platforms.

 

A software design challenges lies in establishing a single platform for game management accessible from multiple platforms.  The application must support simultaneous user instances that span across multiple teams and platforms, ensuring unique features such as team names and session instances. 

 

Proposed Solution

I propose leveraging a secure cloud-based data and storage service to utilize as the host for the game's application and interface. Furthermore, I propose a reversioning of current game code to move it to a platform-agnostic framework allowing for a unified code design, friendly to all web-based browsers and Android platforms. This design allows for an accelerated expansion of current design and features across desired platforms.

 

Requirements

 

To meet the needs of CTS and The Gaming room, the design must meet the following requirements:

●        Cloud-based platform – The back-end application must be stored ad ran from a cloud-based OS

●        Single codebase – Coding should be done primarily through a platform-agnostic framework, allowing for utilization of a centralized location for instruction and management of the application

●        Security and Privacy – Development must meet all regions' security, privacy and payment system requirements through secure user authentication portals and platforms.

●        Unique Game elements- In order to run successfully, mechanisms need to be in place to support unique game elements to include but not limited to:

o   Game instances

o   Team Names

o   User Names

●        Minimize expenditures – overall expenses should be limited until increased revenue streams arrive. This will include but not limited to

o   Hardware requirements

o   Development costs

o   Cloud infrastructure

 

Design Constraints

Based on the identified application requirements, the following constraints will be applied to the applications design:

●        Cloud-based Infrastructure – A requirement to keep costs minimal forces a dependency on a cloud-based infrastructure, avoiding costs associated with Virtual Machines, (VMs) or physical servers.

●        Single Codebase – A platform-agnostic framework needs to be utilized to enforce single instance development across multiple desktop platforms and browsers.

●        Strict Data Integrity – unique elements must be upheld throughout development to ensure compliance with local and regional data regulations.

 

Implications for Design and Development

 

Each of the previous constraints translates into the following implications for the design and development team:

●        Cloud-based Infrastructure – Coding must be logical and concise, minimizing server call instances, and speeding up game elements.

●        Single Codebase – Testing time must increase beyond that allowed for single platform development to ensure complete testing and debugging across multiple platforms and browsers. Testing must include multiple configurations of players, browsers and platforms to ensure compatibility and response times between configurations.

●        Strict Data Integrity – A trusted third-party authentication and payment system must be integrated early to ensure regulatory compliance.

Domain Model

 

The following UML Diagram for The Gaming Room's Win It or Loose IT application will serve as the basis for the code implementation and design.

 

●        Abstract Class (Entity) serves as a root directory for all game objects. In this diagram these include the classes Game, Team, and Player.

o   Attributes in this class (id and name), ensure unique game identifiers for each instance.

o   Methods for this class include the getters, (getID() and getName()), and constructors of Entity(id: long, name: String)

o   Game Class allows for a single instance of the game.

▪          Attributes in this class are inherited from Entity (id and name)

▪          Methods in this class include commands to add teams to the instance (addTeam(name:String): Team)

o   Team Class allows for a unique team instance to be created.

▪          Attributes in this class are inherited from Entity (id and Name)

▪          Methods in this class allow players to be added to a team (addPlayer(name: String): Player)

o   Player Class allows for a unique user to be added into a game instance

▪          Attributes are inherited from Entity (id and name)

●        A Singleton Manager, (GameService), will be utilized to control all instances and interactions

o   Attributes create a list of game elements for game instances (nextGameID, nextPlayerID, nextTeamId) and the static instance (service: GameService)

o   Methods (addGame, getGame, getGameCount, getNextPlayerID, getNextTeamId) assist with the fundamental instance options to Create, Read, Update and Delete information.

●        SingletonTester and ProgramDriver are separate classes where the ProgramDriver uses SingletonTester for execution and verification of instances.

o   ProgramManager contains the main() method to start the application

o   SingletonTester verifies only a single instance of GameServices exists

 

This design allows for instances controlled primarily through Inheritance and Aggregation. Using Inheritance, we see that the Game, Team and Player classes all inherit their attributes from Entity. This relationship ensures all data is managed security and can be managed with a single set of security requirements.

 

Game and Team demonstrate Aggregation where Game contains Team objects. The multiplicity shows us a 0 to many relationships, implying we can have any number of teams in the game. Team meanwhile, has a zero to many relationships with Player.  Meaning that a team may have multiple players in any single instance.

 

The ProgramDriver uses SingletonTester to verify the instances of the GameService. While GameService manages all objects within the List<Game>.

 

Using Inheritance with the Entity base class, we can control access to use and create unique game elements. Encapsulation within the game design supports legal and security requirements from outside methods or calls for information. The Singleton Pattern ensures only a single instance of a Game, Team or Player, ensuring resourcing constraint requirement are met (data and resource processing time).

Server Side

While macOS offers a highly stable and secure operating system with known resistance to malware, it presents significant roadblocks for The Gaming Room's expansion goals. The primary disadvantages are the increased expense resulting from higher licensing costs. More critically, the platform is not designed for the efficient, large-scale distributed environment required, and it has a known weakness regarding application scalability. These factors, combined with limited software compatibility, render macOS an impractical choice for our server-side hosting solution.

Linux offers a highly cost-effective and structurally sound foundation for our application server. As an open-source platform, the primary advantage is the elimination of high operating system licensing fees, allowing resources to be shifted toward ensuring scalability. Linux is known for its stability, security, and reliability in hosting web applications, making it an excellent platform for our goal to scale this application. Additionally, its open-source nature promotes compatibility with the majority of required tools and platforms.

The main challenges associated with Linux is its Command-Line Interface (CLI) which may require specialized expertise compared to the Graphical User Interface (GUI) of other platforms. An additional complication may arise from, the lack of standardization across devices. This is a mild concern compared to the licensing costs with other products.

Windows Server offers a robust infrastructure with native integration with the Microsoft Office suite. Its infrastructure provides a stable framework for web hosting and high security protocols Its framework is capable of handling the demands of a scalable web-based application. The primary disadvantage is the significant price of licensing costs compared to open-source alternatives like Linux. These costs make Windows one of the least cost-effective options for server-side hosting. Additionally, system updates can occasionally lead to compatibility issues with various platforms or browsers. Additionally, this OS generally requires more hardware resources to run efficiently, adding to the total cost of use.

Recommendations

 

Analyze the characteristics of and techniques specific to various systems architectures and make a recommendation to The Gaming Room. Specifically, address the following:

 

Based on the above analysis for The Gaming Room’s expansion of the Draw It or Lose It application, I recommend the following systems to ensure your project goals are met: scalability, security and cost-effectiveness.

 

  1. Operating Platform: I recommend the Linux Operating System (OS) for the application's server environment. Linux offers the best combination of cost-effectiveness (due to minimal licensing fees), high security, reliability, and compatibility with the required development tools and operating systems.
    1. Linux, as an open-source platform, Linus eliminates high licensing fees.  Licensing fees constitutes a large portion of costs from other platforms.  Eliminating licensing fees allows funds to be shifted as needed towards development and scalability, reducing overall costs and directly supporting the project’s requirements to minimize overall costs.
    2. Linux is known to be a stable, secure, reliable platform for hosting web applications. It’s open source allows for a wide range of compatibility options both with other operating systems and with development tools. This combination allows for a dependable base platform for development.

 

  1. Operating Systems Architectures: The application should be hosted using Linux as a Virtual Machine (VM). This provides essential benefits for scalability and resource management. Utilizing a VM assists with resource constraints while allowing efficient application hosting for the server.
    1. Linux uses a monolithic kernel. This means the entire operating system operates within the same protected space. This minimizes server calls, and increases performance and efficiency.  A high performance system is required to be able to handle multiple, simultaneous instances across platforms.  A monolithic kernel also increases security by removing interactions between different systems when accessing core services such as memory, file management, device drivers and process communications.
    2. Using a Virtual machine fills the project requirements for scalability and resource constraints. A Virtual Machine separates physical hardware from the operating system allowing for a simplification during application development.

 

  1. Storage Management: I recommend using a cloud-based storage system with the VM. Many cost-effective storage systems are scalable and provide robust security and reliability. They typically include support options for game development and asset backup, ensuring minimal downtime and game interruptions compared to other services.
    1. A cloud-based storage system in conjunction with a VM ensures data integrity is maintained throughout the life of the application. This becomes especially important with reversioning and protection against outages and system failures.
    2. Cloud storage is cost effective and scaleable.  Most cloud-based storage plans include an additional security layer of their own, as well as support for system back-ups and development. 

 

  1. Memory Management: Memory management within Linux VM is crucial for system stability and resource management.
    1. The system achieves process isolation by assigning the game its own unique address via the kernel, maintaining security and stability in its use of a single instance of the game, utilizing a Singleton Pattern to facilitate game play.
    2. This process may be further divided into smaller units, (pages), which allows for calls to be made to specific units as needed, ensuring data is kept safe and improving overall efficiency.
    3. Memory is allocated to a shared library system, which hosts common elements like the Singleton Manager. This practice reduces the need for duplicate code and overall memory consumption.

 

  1. Distributed Systems and Networks: The application utilizes a three-tiered distributed system to manage communication and data flow across multiple platforms:
    1. Client Tier: The user interface runs on a standard web browser and platforms, facilitating communication with the application server via secure protocols, such as HTTPS.
    2. Application Tier: The application server runs on a Linux-based VM. It hosts the game, its elements, and instances, managed efficiently via the Singleton Manager (GameService).
    3. Data Tier: The application manager communicates with a cloud-based data storage center to securely store all current and historical data.

 

●        Communication between these systems and applications must be fast and reliable for optimal gameplay, creating a dependency on the cloud server and network speeds.

●        To minimize disruptions that can impact data integrity and reliability, network calls should be limited as much as possible, including combining elements into a single call when feasible.

 

  1. Security: Security requirements must be maintained across the design through integrated processes and structures.
    1. To ensure security and privacy are maintained, all applications must be integrated and authenticated using trusted third-party processes. Performing this step early ensures the encapsulation process supports legal and data privacy laws.
    2. Access to gameplay and user information is strictly controlled using unique identifiers that can only be accessed through the inheritance structures built from the Entity Class. This ensures that security is maintained and controlled throughout the application.
    3. The Linux Operating system, cloud storage, and all systems and programs within this project will utilize standard measures such as data encryption, firewalls, and built-in security protocols to maintain the confidentiality of all data sources.
